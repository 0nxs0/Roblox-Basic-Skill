# Case Study - Piggy — Development Guide

New practical guidance for [[02 Game Design and Economy/Foundations Planning/Community Knowledge/Case Study - Piggy|Case Study - Piggy]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
Piggy (MiniToon, Kohl Couture) is an episodic horror escape game: players solve item puzzles to escape a map while one player or a bot plays Piggy, the hunter. It matters because it proved that weekly story chapters on Roblox can build a huge fandom fast, and that a creator's own channel can be the main growth engine.
**Useful source sections:** Snapshot (Roblox page, seen 2026-10-25), Core loop, Session shape.

## Apply it
Use this topic as part of **make fair, measurable player loops**.
- **Define the contract:** For Case Study - Piggy, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Map action, feedback, reward, and next choice; define cost, pacing, and a success measure.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Check exploits, runaway rewards, and no-spend fairness.

## Validate before shipping
- **Expected path:** Build one small feature using Case Study - Piggy and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Test first play, repeat play, and edge-case balances.
