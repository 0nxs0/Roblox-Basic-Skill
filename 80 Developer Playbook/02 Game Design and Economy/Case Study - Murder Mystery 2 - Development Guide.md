# Case Study - Murder Mystery 2 — Development Guide

New practical guidance for [[02 Game Design and Economy/Foundations Planning/Community Knowledge/Case Study - Murder Mystery 2|Case Study - Murder Mystery 2]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
Murder Mystery 2 (Nikilis) is a round-based social deduction game: one Murderer, one Sheriff, everyone else Innocent. It matters because a 2014 game with simple rounds still sits near the top of the platform, carried by a knife and gun collection economy that is traded like currency.
**Useful source sections:** Snapshot (Roblox page, seen 2026-10-25), Core loop, Session shape.

## Apply it
Use this topic as part of **make fair, measurable player loops**.
- **Define the contract:** For Case Study - Murder Mystery 2, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Map action, feedback, reward, and next choice; define cost, pacing, and a success measure.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Check exploits, runaway rewards, and no-spend fairness.

## Validate before shipping
- **Expected path:** Build one small feature using Case Study - Murder Mystery 2 and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Test first play, repeat play, and edge-case balances.
