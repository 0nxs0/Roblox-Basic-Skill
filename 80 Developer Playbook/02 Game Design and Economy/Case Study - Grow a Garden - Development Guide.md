# Case Study - Grow a Garden — Development Guide

New practical guidance for [[02 Game Design and Economy/Foundations Planning/Community Knowledge/Case Study - Grow a Garden|Case Study - Grow a Garden]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
Grow a Garden is an idle farming game that went from about 500 concurrent players to the biggest concurrent audience any game had ever recorded within months of its March 2025 launch. It matters because the core idea is simple enough for anyone to copy, so the lessons are in the details: offline growth, timed shop restocks, visible gardens and weekly live updates.
**Useful source sections:** Snapshot (Roblox page, seen 2026-10-25), Core loop, Session shape.

## Apply it
Use this topic as part of **make fair, measurable player loops**.
- **Define the contract:** For Case Study - Grow a Garden, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Map action, feedback, reward, and next choice; define cost, pacing, and a success measure.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Check exploits, runaway rewards, and no-spend fairness.

## Validate before shipping
- **Expected path:** Build one small feature using Case Study - Grow a Garden and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Test first play, repeat play, and edge-case balances.
