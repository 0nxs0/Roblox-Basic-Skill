# Using Brands, the Roblox Name and Licensed IP — Development Guide

New practical guidance for [[13 Growth and Monetization/Publishing Release/Community Knowledge/Policy - Using Brands, the Roblox Name and Licensed IP|Using Brands, the Roblox Name and Licensed IP]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
Real cars, real guns, famous characters, logos on shop signs, and "Roblox" in your title are all common in Roblox games, and all are IP risks. There are three separate questions: can you use Roblox's brand, can you use someone else's brand, and can you get a license to do it properly.
**Useful source sections:** Roblox's own brand, Other people's brands and characters, Getting a license: the Licenses catalog.

## Apply it
Use this topic as part of **improve discovery without misleading players**.
- **Define the contract:** For Using Brands, the Roblox Name and Licensed IP, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** State the audience promise and first-session value; measure one funnel step before offers.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Show price and benefits clearly, respect platform rules, and avoid coercive timers.

## Validate before shipping
- **Expected path:** Build one small feature using Using Brands, the Roblox Name and Licensed IP and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Compare conversion with satisfaction and test no-spend progression.
