# Thumbnail Personalization and Icon Testing Workflow — Development Guide

New practical guidance for [[13 Growth and Monetization/Thumbnails/Deep Dives/Thumbnail Personalization and Icon Testing Workflow|Thumbnail Personalization and Icon Testing Workflow]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
Discovery prerequisites: a custom thumbnail is required to get RFY impressions at all, and mismatched metadata or "giveaway" framing reduces exposure (see Home Recommendations - What Roblox Documents About Discovery).
**Useful source sections:** Why this matters, 1. Specs and limits (Creator Docs › Thumbnails, Icons), 2. How thumbnail personalization works.

## Apply it
Use this topic as part of **improve discovery without misleading players**.
- **Define the contract:** For Thumbnail Personalization and Icon Testing Workflow, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** State the audience promise and first-session value; measure one funnel step before offers.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Show price and benefits clearly, respect platform rules, and avoid coercive timers.

## Validate before shipping
- **Expected path:** Build one small feature using Thumbnail Personalization and Icon Testing Workflow and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Compare conversion with satisfaction and test no-spend progression.
