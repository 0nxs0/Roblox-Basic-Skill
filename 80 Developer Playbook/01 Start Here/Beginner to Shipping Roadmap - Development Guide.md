# Beginner to Shipping Roadmap — Development Guide

New practical guidance for [[01 Start Here/Community Knowledge/Beginner to Shipping Roadmap|Beginner to Shipping Roadmap]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
"Where do I start and what do I learn next?" is the most common beginner question. This roadmap turns it into seven stages, each ending with a shipped thing rather than a finished tutorial, because finishing small games teaches what tutorials cannot: scope, bugs under real players, and publishing. Each stage lists the skills, the project, and the vault notes to use. Time estimates are rough guides for a few hours...
**Useful source sections:** Stage 0: Studio comfort (week 1), Stage 1: first scripts (weeks 2-3), Stage 2: ship game #1, an obby (weeks 3-5).

## Apply it
Use this topic as part of **connect learning to playable results**.
- **Define the contract:** For Beginner to Shipping Roadmap, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Choose a learning goal and prove it in a small vertical slice; record prerequisites and next steps.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Practice references in a disposable place and note version assumptions.

## Validate before shipping
- **Expected path:** Build one small feature using Beginner to Shipping Roadmap and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Can a new developer produce a testable feature?
