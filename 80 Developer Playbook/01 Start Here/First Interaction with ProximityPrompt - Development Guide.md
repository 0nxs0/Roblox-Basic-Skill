# First Interaction with ProximityPrompt — Development Guide

New practical guidance for [[01 Start Here/Community Knowledge/First Interaction with ProximityPrompt|First Interaction with ProximityPrompt]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
"Press E to open", "Hold E to pick up": that floating prompt is a ProximityPrompt, and it is the easiest correct way to make objects interactive. It handles distance, the key/button icon for every device (keyboard, touch tap, gamepad), hold timers and line of sight, and it hands your server script the player who used it. For beginners it replaces fragile `Touched` triggers and click detectors for most "use this"...
**Useful source sections:** Add one (1 minute), Script it (server Script inside the prompt), A door that opens and closes.

## Apply it
Use this topic as part of **connect learning to playable results**.
- **Define the contract:** For First Interaction with ProximityPrompt, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Choose a learning goal and prove it in a small vertical slice; record prerequisites and next steps.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Practice references in a disposable place and note version assumptions.

## Validate before shipping
- **Expected path:** Build one small feature using First Interaction with ProximityPrompt and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Can a new developer produce a testable feature?
