# First Obby in 30 Minutes — Development Guide

New practical guidance for [[01 Start Here/Community Knowledge/First Obby in 30 Minutes|First Obby in 30 Minutes]]. This companion adds a build and validation plan; use the linked source for full reference detail.

## Source-grounded context
An obstacle course ("obby") is the classic first Roblox game because it teaches building, anchoring, a kill brick, checkpoints and a leaderboard without any networking. The goal here is a complete small game in half an hour: 5 stages, lava, checkpoints that remember your stage, and a stage counter. Polish comes later; finishing comes first.
**Useful source sections:** Minute 0-5: setup, Minute 5-15: build 5 stages, Minute 15-22: one script for all lava.

## Apply it
Use this topic as part of **connect learning to playable results**.
- **Define the contract:** For First Obby in 30 Minutes, write down behavior, inputs, state owner, visible result, and failure response.
- **Build a first slice:** Choose a learning goal and prove it in a small vertical slice; record prerequisites and next steps.
- **Maintain it:** Separate tuning data from behavior, record assumptions, and provide cleanup or rollback before connecting more systems.
- **Project risk:** Practice references in a disposable place and note version assumptions.

## Validate before shipping
- **Expected path:** Build one small feature using First Obby in 30 Minutes and record setup and expected result.
- **Boundary case:** Test missing, invalid, repeated, delayed, or interrupted input where relevant.
- **Integration:** Test with neighboring systems and at target device/player scale.
- **Acceptance check:** Can a new developer produce a testable feature?
